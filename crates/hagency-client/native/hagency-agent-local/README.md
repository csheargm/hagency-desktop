# Owner-local agent execution controls

This crate uses a new SQLite application ID and schema. It rejects old Hagency databases and permanently binds its database to the authenticated Matrix owner. It has no Fleet, Engagement, resource approval, transfer or server administrator interface.

The desktop host authenticates the owner through Pasion/Hagency, fetches an owner-scoped Agent/binding record from the server, and calls `register_binding`. Scope values must come from verified server envelopes and Matrix sender IDs, never model output or nicknames. A policy/approval UI must call owner-only APIs from the trusted desktop process; a model child process must not receive these APIs or the database path.

## Runtime contract

1. The production Matrix host uses `BudgetMode::Postpaid`: `begin_postpaid(scope, call_id, dispatch_id, now)` checks known consumption only when a new task is admitted. Agent, Room and requester limits intersect; missing limits are unlimited. `Tokens(0)` prevents new tasks. No estimate is held, and an admitted native reasoning/tool loop may finish above its limit. Subsequent calls within that same authenticated dispatch retain admission. Owner request denials and tool approval checks still apply.
2. Only `Reservation::New` permits transmitting model input. Pending, settled or unknown calls cannot be replayed. Call identity includes the original scope, dispatch and accounting mode. The older `reserve`/`Estimated` APIs retain their original digests and hold semantics for explicitly selected legacy callers; the Matrix host no longer selects them for execution, even when restoring an old startup preference.
3. `settle` charges actual provider usage once to the call's original day/month/lifetime accounts, including any overrun. Cached input and reasoning output are subsets, not additional charges. A changed receipt cannot overwrite a settled call. A late known receipt can settle a previously unknown call once.
4. On uncertain outcomes call `mark_unknown`; exclusive restart uses `recover_interrupted`. Missing usage stays unknown, never becomes a known zero. Postpaid calls hold zero tokens while awaiting measurement. Historical estimated holds and their original records remain intact; they are not treated as known consumption for new postpaid admission.
5. Context keys isolate owner, Agent, binding, Room, requester and thread. Context retention is independent of each call's accounting. Filesystem and network permissions still require the authenticated host boundary; a context key alone is not a sandbox.
6. A dispatch snapshots its request/tool policies. Later widening cannot upgrade its authority; tightening is checked for subsequent calls/tools. Owner approvals bind scope, dispatch, exact arguments, policy revisions and expiry. Tool approvals are single use; a Matrix answer to a question does not grant tool authority.
7. Model profiles contain credential references and local workspace metadata. Resolve credentials in the trusted host; never give a model child the owner ledger or Matrix/device tokens.

## Native adapters

Codex and Claude retain their native reasoning, tools, instructions, extensions, sessions and context compaction. The host supplies authenticated Matrix input and approval/question bridges. Successful measured personal turns can retain their native process for follow-up messages; each new dispatch has separate admission and usage settlement. Idle processes retain no call quota or per-call file authority. Failed or uncertain turns retain their accounting evidence and do not enter the warm cache.

`BudgetMode::Postpaid` is the production billing policy. `Strict` remains an explicitly unsupported hard-cap request; it fails before model work. `Estimated` is retained for legacy callers and tests, and is not a maximum-charge guarantee. Saved startup estimates remain comparable during recovery but do not re-enable reservation accounting in the Matrix host.

Usage must come from complete native receipts, including descendant work. Historical context occupancy is not billable usage. Cold Codex resumes without complete response receipts remain unknown; postpaid accounting keeps that measurement gap from freezing other work. Claude's supported whole-session usage snapshots are correlated to the original native session and call. Native permissions remain bound to the original owner and request.

The personal Matrix host connects both Codex and Claude to the shared history/document reader and durable file-transfer implementation. `read_room_history`, `list_received_files`, `receive_file`, `send_file` and `get_file_delivery` use the admitted room, requester, workspace and dispatch; model arguments cannot replace those identities. Every operation rechecks current execution authority. The current request's own attachment is indexed as well as older room messages. File receipts preserve the original transaction and immutable bytes across uncertain delivery and restart. Plain and encrypted rooms use the Agent's device; publishing rejects a change in the room's expected encryption state.

Codex uses a process-owned localhost MCP endpoint so both new and restored native contexts receive the tools without resetting the conversation. Calls require a private capability plus an active native thread/turn observed on the original app-server stream; completion/cancellation retires that authority. Owner/project MCP configuration is preserved and a reserved-name collision is rejected. Claude uses its native SDK MCP callbacks and original source-bound replies. Only the exact host Matrix tools inherit this dispatch's room authority; other tools retain their ordinary owner approvals. Idle sessions retain definitions, never an active room-tool queue. Codex context-occupancy observations refill history allowances after native compaction; absent such evidence the reader keeps its conservative bounded allowance.

Tests include disposable installed Codex/Claude localhost model fixtures, warm/cold Codex context restoration, Claude continuous callbacks, cancellation and file receipt replay. They do not establish live River delivery or provider entitlement. Shared Claude and live encrypted Matrix qualification remain separate work.

## Durable local inbox contract

The `inbox::Dispatch` serde shape matches the new server transport envelope. The trusted device transport verifies its owner/device/Agent lease and fetches the owner-scoped binding before passing the envelope to this crate. The envelope cannot authenticate its own owner. `Dispatch::scope()` uses the real requester MXID and Room/thread identifiers.

1. `receive_dispatch(owner, event, limits, now_seconds)` validates the registered local binding and permanently records immutable event/scope/body/binding-generation identity, returning a `Receipt`. **Only after this returns successfully may the host send server ACK.** Changed payload with the same dispatch ID, or another dispatch ID for the same binding/event, conflicts. Capacity rejection returns no receipt. Record capacity counts active records; byte capacity includes retained envelope/reply UTF-8 payload and a conservative proof allowance for every record, including terminal deduplication receipts. SQLite page/index/WAL overhead is separate.
2. After an acknowledged server ACK, call `acknowledge_dispatch`. A lost ACK response can be retried using the same durable event. Delivery epoch/device may advance while an event is received/acknowledged; late older delivery cannot overwrite a newer epoch. Once prepared, lease metadata is frozen.
3. `prepare_execution` requires acknowledged state and writes a stable random execution ID **before** posting server start. Repeated calls while prepared return the same ID. `confirm_execution_start(owner, ServerStart)` validates the complete response identity, binding generation, execution ID, epoch and device. Only `newlyStarted=true` plus local prepared state returns a non-cloneable `RunPermit`. Concurrent confirmation readers yield exactly one permit. `newlyStarted=false` never starts a model; a prepared record becomes unknown. Repeated true responses in running state also return no permit.
4. Consume the permit into its `Prepared` descriptor, use that stable execution ID as the Codex turn call ID, and its original dispatch/requester scope for every model/tool action. The host must keep execution identity separate from thread/model-session identity.
5. Before sending a server reply, call `persist_execution_reply`. The reply becomes durable `reply_ready` and has immutable digest/content. On a lost HTTP result, retry that same execution/reply, never another model turn. `confirm_matrix_delivery` may be invoked only after the host verifies a scoped `sent` receipt with a Matrix event ID. Server outbox acceptance keeps `reply_ready`; it can later need reconciliation after lease expiry. After this trusted sent proof, the terminal receipt retains identity, immutable original digest, execution and reply digest while clearing duplicated plaintext. Exact redelivery cannot mint a new execution and changed content still conflicts. Unknown execution identities remain permanent; terminal request bodies with settled or absent usage may be compacted. Missing local historical receipts remain unmeasured and do not block new work; server execution custody prevents replay and every available local accounting proof is still validated. Unsent known replies retain their original text. A changed reply conflicts. `inbox_by_state(ReplyReady)` supports outgoing retries independently of interrupted records.
6. `finish_local_execution` records rejected, failed or unknown dispositions; it does not fabricate zero usage or release model reservations. Send the matching server finish request separately. On an exclusive device restart, `recover_local_executions` atomically seals local prepared/running work as unknown and keeps pending provider usage unresolved. Received/acknowledged requests and already durable replies survive for ACK/dispatch/reply reconciliation. Unknown cannot transition back to running.
7. Use the circular `inbox_for_binding_after` recovery scan to bound historical retries and leave new polling free to progress; `inbox_pending` is a bounded combined reconciliation view. Preflight `inbox_available_bytes` before model work and handle a full reply store by retaining the known result for owner recovery, never regenerating it. The byte preflight is a snapshot rather than a capacity reservation; concurrent new events can still exhaust capacity. The host exposes `inbox_capacity` for active/terminal receipt counts and charged bytes. Permanent metadata still consumes storage; this is not unlimited historical retention or secure disk erasure.

The pure library implements no network polling, device authorization refresh, lease heartbeat, event expiry policy, retention cleanup or external secret store. These operations belong to the authenticated trusted host. No old Fleet/Engagement data or sessions are imported. Tests use real SQLite connections and process-like reopen/recovery to verify ACK durability, one concurrent execution permit, unknown no-replay, immutable reply retries, wrong owner/scope/lease, and payload capacity.

The new trusted desktop host lives in `native/hagency/src/console/owned_runtime.rs`. It uses an explicit owner start and estimate selection, fresh authenticated device operations, a per-Agent lease heartbeat and scoped recovery. Provider credentials use Codex's own OS keyring entry keyed by the canonical dedicated `CODEX_HOME`; `Profile::spawn` forces `cli_auth_credentials_store="keyring"` without file fallback. The host verifies the credential locator against its exact owner-specific directory and then requires `account/read` to report an account before announcing chat availability. A locator is not itself proof of login, and account presence does not guarantee a future provider request will succeed. No credential values are read by this library.

`recover_agent_executions` is the restart operation for one independently leased Agent; it preserves other Agents' active calls. `inbox_for_agent` selects bounded work for that Agent so another Agent's backlog cannot starve it. The host stops provider execution on cancellation or loss of authorization/lease. Durable original replies retry transport failures while the original lease is still usable. Cross-epoch known-reply reconciliation uses the separate server endpoint with the original immutable execution/body/binding generation/epoch and the current owner/device lease. An accepted but unsent reply remains `reply_ready`; it is terminal only after a scoped Matrix `sent` proof. Unknown executions never run their model again.

## Scoped host dynamic files and owner approvals

`Session::enable_host_files(Workspace, Arc<dyn HostToolGate>)` is a trusted host attachment before opening the provider context. It advertises only `hagency_file_list`, `hagency_file_read`, and `hagency_file_create` through the installed 0.160 dynamic-tool protocol. Model arguments cannot select a root, credential or create nonce. `Workspace` holds a binding-specific root FD beneath the verified owner directory; the host process cwd uses that generated root. Native shell, file/image, web search, MCP, hooks, plugins, app and subagent capabilities remain disabled. Host files do not imply an unrestricted native OS sandbox qualification; replacement is unsupported.

Every `item/tool/call` is pinned to its exact Codex thread/turn/call and the Matrix owner/Agent/binding/Room/requester/thread context. `HostToolGate` must obtain fresh server authorization for the original running dispatch/execution before IO, and again after any owner wait. `Workspace::prepare` binds arguments, root, three policy revisions and expiry into the proposal. `Workspace::execute` consumes the precise local permit itself. Deny never reaches an approval prompt; exact allow-rules can authorize automatically; AskOwner parks the original proposal in the owner host queue. A repeated call with changed arguments is rejected. A proved creation receipt can return the original result without creating or consuming another permit; an unproved publication seals uncertainty instead of blindly replaying.

`OwnedRuntime::pending/decide` exposes opaque random proposal IDs and a digest of the complete original proposal. The host verifies owner cookie, current Pasion subject/device/generation, Agent and active binding before consuming the one-time decision. The adapter then rechecks remote scope and local revisions. Model requests use the same UI queue with `tool="model.request"` and `risk="model_request"`, but authorize with `Ledger::approve_request_exact`, not a high-risk tool permit. Changing request parameters, requester, Room, policy revision or execution cannot reuse a confirmation.

Tool-enabled provider contexts and usage baselines use the separate `hagency-room-files-v1` key; existing chat histories are retained. The adapter explicitly selects Codex's JSONL history mode (`historyMode="legacy"`, unrelated to historical Hagency data), materializes a fresh thread by its metadata update, and verifies the same scope on resume. If the provider explicitly confirms that this exact stored thread no longer exists, a new thread serves the current new request and starts its own cumulative baseline; historical charges and executions remain unchanged. Arbitrary resume errors never clear context or accounting. The native runtime retains its configured project instructions, skills, MCP servers and features. The host validates the returned native context and approval identity before use.

The inference-free `codex_host_files_handshake` example validates real installed dynamic-tool registration, independent context creation, effective config, and cross-process resume without model or file-tool calls. Fake protocol tests exercise actual host file effects, denial and revocation during owner approval, duplicate/changed calls and real usage settlement. Strict provider token caps remain unavailable. The Matrix host uses postpaid admission and allows each admitted task to finish; unreported usage remains unresolved until actual evidence arrives.

## Initialization and terminal inbox retention

Fresh schema detection runs after acquiring SQLite's immediate transaction lock, so concurrent first openers reuse the committed schema and its permanent owner/profile identity. Rejected requests with an exact no-provider-call proof, and failed/interrupted requests with an exact settled usage/scope/snapshot/account proof, compact their request body without deleting execution IDs, immutable digests, call settlements or budget balances. These compact terminal receipts do not consume active record slots; their retained metadata still consumes the byte limit. Interrupted records never consume active work slots. Unsent original replies retain their full payload and active slot; failed records without a settlement proof retain their payload. Missing usage receipts remain unresolved in continuity checks; execution scope and available accounting proofs are still validated.
