This seventh release candidate replaces rc.6, whose macOS installer could not find the images and fonts packed inside the app. It is otherwise the same as rc.6, which added Claude Code as an Agent runtime beside Codex, as local Agents and as shared pools. It is the first release candidate built on the new Makepad engine line, it keeps Matrix sign-ins in the operating system's credential store, and it fixes a number of chat and Agent-panel defects. It retains the file exchange, question cards and integrated macOS hosting from rc.5.

**Read before upgrading**

- **Hosting set-up from rc.5 or earlier is not carried over.** At its first start this build discards the earlier build's resource database, the grant and enrollment journals bound to it and its initializer record, without asking, and begins as a new installation: set up hosting, resources and pools again. Matrix sessions and keys, provider sign-ins, room history and work files are kept. A local-Agent usage record that an earlier build locked as an archive is replaced by an empty one. On a server that supports ledger declarations, the pools and grants published from the discarded database are ended.
- **Saved sign-ins move into the operating system's credential store at first start, one way.** An earlier build can then no longer open that profile. The macOS build is ad-hoc signed, so macOS treats each new build as a different program and asks for the login password for every saved item after an update.
- The execution machine needs Claude Code 2.1.322 or later and Codex 0.167.0 or later. An older CLI is refused with a message that names the required version.
- Agent features were run against a Hagency server at schema 35. Pooled Claude Agents also need the server to accept a never-started proof for grant version 6; that rule is not in the server repository's main line yet.

**Fixed in rc.7**

- The macOS app finds the files packed inside it. In the rc.6 macOS installer the sign-in logo, icons and other images were missing and text was drawn in system fonts instead of the bundled ones, on every Mac except the one that built it: the package was built with a resource folder setting that the new engine does not use. The Windows installer of rc.6 was not affected. The automated installer check now fails a package that does not draw its bundled logo.

**New in rc.6**

- Claude Code Agents. A resource owner can run a local Claude Agent, or publish a pool from "Claude Code on this computer". The pool uses the owner's own Claude Code configuration, read at each launch: an API key, a custom endpoint token (for other models behind a compatible endpoint), or the owner's claude.ai sign-in. **Anthropic's consumer terms do not allow making an account available to other people; putting a claude.ai subscription sign-in behind a shared pool is the owner's own decision and risk.** An API key under the owner's own agreement does not have that problem.
- Shared Claude runs are confined to the Agent's own work folder for writes and can reach the network. An owner can give a Claude Code pool or a pooled Claude Agent full trust; tools, shell commands included, then run without asking the owner.
- Local Agents work beside pools. An owner's local Codex, Claude Code or Octos Agent can be added to a room, and other members of that room can call it. Tool rules can be set per room and per member, down to asking the owner for every tool call.
- A message sent while a Claude turn is running joins that turn, as it already did for Codex. The owner's own message that starts with `/` reaches their local Claude Agent as a slash command. A shared turn ends after one hour.
- The run panel shows the live answer formatted and lets it be selected. The owner's usage report lists each pooled Claude call.
- Coding Tools lists Claude Code and is laid out as grouped lists. A pool whose server connection is closed can be deleted, and an owner can publish a further pool of the same Claude model. A person picked for a pool's list keeps the exact account name the server returned, capital letters included; before, such a name was lower-cased and publishing failed with "An account on the list no longer exists".
- Runs are harder to lose: a turn survives one unanswered validity check or a brief authority failure, a run that starts during a token refresh is no longer ended, Stop on a Codex run no longer leaves the Agent silent, hosting can be resumed after a stop, and the macOS owner daemon no longer runs as a low-priority background job.
- Chat: your own messages sit on the right with your avatar at the edge, the chat column has wider side padding, the room list snaps fully shut when its divider is dragged to the edge, and mini-app buttons and sliders keep their shape. A restored thread tab no longer stays on "Waiting for this room to be loaded", and open rooms let the window go idle again.
- Chinese and other composing input methods work on the new engine: a committed word is no longer overwritten by the next one.
- From the main line since rc.5: Matrix links open rooms and threads in the app, device verification and recovery, Space filters, reactions and moderation, bounded attachment downloads and chat caches, lower idle CPU and memory, explicitly authorized shared workspaces for local Agents, and a first-time path from sign-in to the Agent page.
- For developers: the same sources run under the Makepad JIT runner (`makepad run`), which patches an edit into the running app. See `.jit/NOTES.md`; fetch the engine checkout with `.jit/sources.sh --outside`.

**Retained from earlier release candidates**

- Attach documents in an Agent conversation and ask the Agent to process them. With tools enabled by the resource owner, Codex can receive the original file in its room workspace and return generated files as encrypted Matrix attachments in the same conversation. Each file is limited to 8 MiB. Sending has a persistent delivery receipt, so uncertain results can be checked without creating duplicate attachments.
- PDF and text attachments can also be read through bounded room-history pages. Long documents are paginated, and encrypted attachments are verified and decrypted with the Agent's Matrix device.
- Agent reply text can be selected and copied in both folded and expanded replies, including formatted content.
- File upload previews fit smaller windows and remain visible above the native browser on macOS. Dismissing the preview restores the same browser page and scroll position.
- The Client runtime now builds as in-tree libraries inside Desktop; its old standalone UI has been removed. Desktop and the integrated macOS owner daemon use the same source revision.

- Agent questions appear as cards below the message that started the run, with choices and text answers. A message can show questions from several Agents. MCP tool approvals and skill-installation approval prompts are refused by this question channel, and Agent accounts cannot answer another Agent's questions.
- Questions in one turn share a ten-minute waiting budget, including opening the encrypted device, retries and answer verification. A slow device or network request cannot extend the question wait beyond that budget.
- Question cards recover their final state after hosting restarts or interrupted requests. An answer is shown as accepted only after it has been delivered back to the running Agent; unanswered cards expire locally even while the network is stalled.
- Desktop retries encrypted cards that could not initially be decrypted when room or device keys arrive. Successful retries appear immediately, and signing out prevents an older account session from updating the current session's cards.
- Long Codex turns stay active while tools are working, and a completed turn's answer is retained when a command is still running.
- Hosting is managed inside **Agent → Hosting**. Desktop and its background daemon use one registered owner resource directory per account on each computer. The daemon can keep the resource pool available after Desktop quits. The separate Hagency Hosting installer is no longer needed.
- Interrupted Agent calls no longer occupy the entire remaining allowance. All Agents count known consumption instead of the call's reservation. A call whose process is confirmed stopped closes at its known consumption, and later usage reports can still add to that amount. **Missing usage counts as zero, so the ledger can understate provider usage and a run can exceed its allowance.**
- A shared message whose previous attempt is proven never to have started can be retried automatically, up to three times, on servers advertising `shared-demand-retry-v1`. Retries retain the same message and queue position. A lost acknowledgement is reconciled through the original request; an attempt that may have executed is not automatically run again. Older servers keep the evidence-only recovery behavior.
- Running Agents have bounded retries for transient authorization checks and can retry an activity renewal with its original request ID. Revocation ends the run immediately. More precise diagnostics distinguish failed authorization stages; these changes do not establish credential refresh as the cause of every interrupted run.
- Background hosting raises its macOS open-file limit, prioritizes unfinished message recovery, bounds provider-report refresh and shutdown, and reuses Agent device credentials across restarts to avoid unnecessary Matrix logins.
- Encrypted room history retains bounded pagination, event deduplication, long-message handling and malformed-event recovery. Codex controls when to compact a room-history thread. The Windows WebView2 reader, window-focus and divider improvements from rc.2 remain included.

Install **Hagency Desktop** for chat, Agent management and macOS resource hosting. Provider accounts and coding tools must be configured on the execution machine. Server-side recovery improvements require a compatible Hagency server; this installer does not update the server or its trusted-proxy configuration.

This RC includes macOS Apple Silicon and Windows x64 installers. Windows background resource hosting, Windows ARM64, Intel macOS, automatic updates and mobile store packages are not included. Signing status is stated above. Local and pooled Codex and Claude Agents were exercised by hand in encrypted rooms on one Apple Silicon Mac against a live server, on development builds of this source; the packaged installers were not. The rc.6 macOS installer was started on a Mac other than its build machine after publishing, which is how its missing images were found. This is the first packaging on the new engine line, and the Windows installer has had no manual acceptance run. Agent question and encrypted-history recovery have offline regression coverage. Automated installer checks do not replace a manual Windows 11 acceptance test or production fault-injection coverage of every recovery path.

The version series remains Hagency 0.5.0, following the inherited Rinx 1.1.x releases. Install this RC manually. The earlier [dependency audit follow-up](https://github.com/hagency-org/hagency-desktop/blob/work/hagency-desktop-local-20261028/dev-vibe/release-0.5.0/assessment.zh.md) remains open.
