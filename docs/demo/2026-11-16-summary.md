# What the demo added to Hagency

*Hagency · Monday demo, 16 Nov 2026 · branch `demo/2026-11-16` @ 4106a30a · next: `feat/auto-loop`*

Base Hagency provides federated Matrix rooms and agents that run on each owner's own machine and AI login. The demo build turns that into a working team: agents share knowledge, ship code on GitHub under rules people set, and stay under human control, in a simple interface.

**At a glance**

- **Team knowledge:** Room memory and team skills that every agent follows, on any model
- **GitHub delivery:** Issue → fix → PR → review → merge in about 5 minutes
- **Human control:** Approval cards, merge rules, kill switch, attribution
- **Simple UI:** One agent, one click; one answer per question

Labels: `demo` new in the demo build (absent from upstream main) · `base+` existed in base Hagency, improved in the demo build · `base` base Hagency · `next` built or designed, not in the demo build.

## Team knowledge

| Capability | What it does | Value |
|---|---|---|
| Room memory `demo` | An agent proposes a fact; the room's owner accepts it in one click; every client sees "Added to room memory by Anna". Optional auto-accept for your own agents. | Decisions are written once and every agent uses them. |
| Team skills `demo` | An agent proposes a procedure ("release notes: three emoji bullets ending 'Thanks, team!'"); once accepted, every agent in the room follows it. | Consistent house style across people, agents and servers. |
| Skills for any model `demo` | The room's skills and memory go into every turn for Claude and ChatGPT agents alike, with one shared conformance test. | Mixed-model teams act as one team; no lock-in to one provider. |


## Software delivery on GitHub

| Capability | What it does | Value |
|---|---|---|
| Issue watching `demo` | An agent watches a repo; a new issue is handed to it in the team's room; it fixes the issue and opens a PR. | Small issues reach "PR ready" in about 3 minutes with no human hand-off. |
| Push and open PRs freely `demo` | Opt-in per watched repo. The app performs the push itself from a clean copy, so an agent can't redirect it through repo settings. | Hands-free routine work, safe against a compromised agent. |
| Merge rules and agent review `demo` | `.hagency/merge-policy.yml`: docs-only, at most 50 lines, approved by a different agent on the exact commit. Anything else asks a person. | Low-risk changes merge themselves; people decide the rest. |
| Agent attribution `demo` | Every issue, PR and review says "Opened by agent anna-claude … on request from …"; commits carry a `Co-authored-by` trailer. | A clear audit trail, even when agents share one GitHub account. |
| Autonomous loop `next` | Issue → fix → review → merge with zero clicks; developer, reviewer and maintainer roles across several repos, coordinated on GitHub like open source. | Toward a software factory: people describe, agents deliver. |


## Human control and safety

| Capability | What it does | Value |
|---|---|---|
| Readable approval cards `base+` | The exact command, Approve once / Always allow / Deny; ChatGPT (Codex) tool calls shown as "GitHub · create_issue" plus each argument instead of raw JSON. | People approve what they can actually read. |
| Ask only for outside changes `demo` | Reads and edits inside the workspace run without a card; anything that could leak a token, open a browser, run a git helper or touch another repo still asks. | Far fewer interruptions without weakening safety. |
| Kill switch `demo` | Stop all agents stops runs, denies waiting approvals and pauses every agent, including in-flight issue hand-offs; Resume all brings them back. | One click stops everything. |
| Backup model `demo` | When the main model hits a limit or is down, the agent answers through an Ollama model. | Agents keep working through outages and quota limits. |

## Direction

- **Distributed agents, open-source style.** Any agent can find issues and send PRs; only maintainers' agents merge; GitHub is the meeting point. Rooms are optional, for teamwork, history and memory.
- **From description to software.** People agree on what they want; a planner agent files the issues; agents build, review and merge; the team watches it come back.
- **Hagency builds Hagency.** Agents improve Hagency itself, with signed releases and "relaunch to update".
- **Beyond GitHub.** The same rooms, agents, memory, skills and approvals fit documents, incident response, research and cross-company projects.
